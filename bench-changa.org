* Introduction

We will be using JUBE in Kabré to run these benchmarks, following the
same tag-gated =base=/=tracing= structure as
[[file:bench-leanmd.org][bench-leanmd.org]].

ChaNGa's build differs from LeanMD's in two ways that shape the
preprocessing step below:

1. It is autoconf-based (=./configure && make=, driven by a
   =CHARM_DIR= environment variable pointing at one of the
   Charm++ variants =building-charm.org= builds), not a plain
   Makefile patched with =sed=.
2. It links against a second dependency, [[https://github.com/N-bodyshop/utility][N-bodyshop/utility]]'s
   =structures= library (Tipsy I/O), which ChaNGa's own CI workflow
   (=changa/.github/workflows/changa.yml=) clones as a sibling
   checkout and points at via =STRUCT_DIR=. It isn't vendored here,
   so it's pulled in as the =deps/utility= submodule.

Because =cha_commitid.c= is generated at build time by running
=git describe= inside the source directory, and because we want each
workpackage's build fully isolated from whatever another concurrently
running node-count/problem-size combination is doing, the preprocess
step below clones =changa= (and copies =structures=) fresh into the
workpackage with =git clone --local= rather than relying on JUBE's
=fileset= copy globs the way LeanMD does — a plain file copy would
lose the =.git= history =git describe= needs, and building in place
inside the submodule checkout would let concurrent runs race on the
same object files.

One wrinkle: by the time preprocess runs, JUBE has already written its
job scripts (=submit.job=, =submit.job.in=) into the workpackage's
=work/= directory — the very directory the preprocess commands execute
in — so it is *not* empty, and =git clone --local $source_dir .= would
abort with "destination path '.' already exists and is not an empty
directory". Instead we clone into a =changa-src= subdirectory, move
just its =.git= into the work directory, drop the now-redundant
checkout, and =git checkout .= to restore the full tracked tree (all
dotfiles included) alongside JUBE's untracked job scripts. The result
is identical to cloning in place, but tolerates the pre-existing files.

*** Preprocessing step

#+name: preprocess
#+BEGIN_SRC yaml :eval no
  - name: preprocess
    tag: base
    _: |
      $modules
      export LD_LIBRARY_PATH=$jube_benchmark_home/deps/prefix/lib:$LD_LIBRARY_PATH
      export PKG_CONFIG_PATH=$jube_benchmark_home/deps/prefix/lib/pkgconfig:$PKG_CONFIG_PATH
      export PATH=$jube_benchmark_home/deps/prefix/bin:$PATH

      git clone --local $source_dir changa-src
      mv changa-src/.git .
      rm -rf changa-src
      git checkout .
      cp -r $structures_dir ./structures
      export STRUCT_DIR=$PWD/structures
      export CHARM_DIR=$jube_benchmark_home/deps/prefix/charm-changa

      sed -i "s/^nSteps.*/nSteps = $nsteps/" testdata/testdata.param
      # testdata.tbin is generated inside testdata/ but the param names it
      # as a bare achInFile that ChaNGa opens relative to the launch cwd
      # (the workpackage root) rather than to the param file -- repoint it
      # at the subdir so the run finds its input.
      sed -i "s|^achInFile.*|achInFile = testdata/testdata.tbin|" testdata/testdata.param

      # testdata's standalone Makefile hardcodes its compile line and
      # predates glibc moving the SunRPC/XDR headers into libtirpc. On
      # hosts where the rpc headers now live under /usr/include/tirpc we
      # point its CC/CXX there by hand (ChaNGa's own ./configure already
      # does the equivalent for its main build) -- a no-op where the rpc
      # headers are still in libc.
      #
      # NB: keep this whole preprocess body free of commas. JUBE splits a
      # parameter value on its separator (which defaults to a comma) into
      # a list -- so any comma here (even inside a comment) chops the step
      # and only a fragment reaches submit.job.
      tirpc_flags=""
      if [ -f /usr/include/tirpc/rpc/types.h ]; then
        tirpc_flags="-I/usr/include/tirpc -ltirpc"
      fi
      make -C testdata N=$problem_size CC="gcc $tirpc_flags" CXX="g++ $tirpc_flags"

      ./configure
      make -j
  - name: preprocess
    tag: tracing
    _: |
      $modules
      export LD_LIBRARY_PATH=$jube_benchmark_home/deps/prefix/lib:$LD_LIBRARY_PATH
      export PKG_CONFIG_PATH=$jube_benchmark_home/deps/prefix/lib/pkgconfig:$PKG_CONFIG_PATH
      export PATH=$jube_benchmark_home/deps/prefix/bin:$PATH

      git clone --local $source_dir changa-src
      mv changa-src/.git .
      rm -rf changa-src
      git checkout .
      cp -r $structures_dir ./structures
      export STRUCT_DIR=$PWD/structures
      export CHARM_DIR=$jube_benchmark_home/deps/prefix/charm-changa-projections
      # charm-changa-projections baked a stale PAPI include/lib path into
      # charmc (from wherever PAPI's pkg-config pointed when charm was
      # built) so expose our own deps/prefix PAPI to the compiler here --
      # CPATH lets gcc find papi.h at compile and LIBRARY_PATH finds
      # libpapi at link (charm++.h pulls in trace.h which includes papi.h).
      export CPATH=$jube_benchmark_home/deps/prefix/include:$CPATH
      export LIBRARY_PATH=$jube_benchmark_home/deps/prefix/lib:$LIBRARY_PATH

      sed -i "s/^nSteps.*/nSteps = $nsteps/" testdata/testdata.param
      # testdata.tbin is generated inside testdata/ but the param names it
      # as a bare achInFile that ChaNGa opens relative to the launch cwd
      # (the workpackage root) rather than to the param file -- repoint it
      # at the subdir so the run finds its input.
      sed -i "s|^achInFile.*|achInFile = testdata/testdata.tbin|" testdata/testdata.param

      # testdata's standalone Makefile hardcodes its compile line and
      # predates glibc moving the SunRPC/XDR headers into libtirpc. On
      # hosts where the rpc headers now live under /usr/include/tirpc we
      # point its CC/CXX there by hand (ChaNGa's own ./configure already
      # does the equivalent for its main build) -- a no-op where the rpc
      # headers are still in libc.
      #
      # NB: keep this whole preprocess body free of commas. JUBE splits a
      # parameter value on its separator (which defaults to a comma) into
      # a list -- so any comma here (even inside a comment) chops the step
      # and only a fragment reaches submit.job.
      tirpc_flags=""
      if [ -f /usr/include/tirpc/rpc/types.h ]; then
        tirpc_flags="-I/usr/include/tirpc -ltirpc"
      fi
      make -C testdata N=$problem_size CC="gcc $tirpc_flags" CXX="g++ $tirpc_flags"

      ./configure --enable-projections
      make -j
#+END_SRC

=configure='s =--enable-projections= toggles the =@PROJECTIONS@=
substitution in =Makefile.in=, but that alone isn't enough: because
=charm-changa-projections= was built against PAPI, its =charm++.h= pulls
in =trace.h=, which =#include <papi.h>=. =charmc= adds a =-I= for PAPI —
but it's the path PAPI's =pkg-config= reported *when Charm++ was built*
(here a stale =/home/casch/papi/include=), not the =deps/prefix= install
=building-charm.org= actually produces, so the header isn't found and
every ChaNGa translation unit fails to compile. Rather than rebuild
Charm++ to correct the baked path, the tracing preprocess prepends our
=deps/prefix= PAPI to =CPATH= (so =gcc= finds =papi.h=) and =LIBRARY_PATH=
(so it finds =libpapi= at link). This mirrors what LeanMD's tracing build
does more directly via its =make projections OPTS="-I…/include $(pkgconf
--libs papi)"= — both routes just ensure the compiler sees the PAPI we
built.

Two environment-specific wrinkles the preprocess works around on Kabré:

- *=testdata= and libtirpc.* =testdata/Makefile= is a standalone,
  pre-autoconf Makefile whose recipe (=$(CC) -o ppartt ppartt.c -lm=)
  hardcodes the compile line and =#include <rpc/types.h>=. Modern glibc
  moved the SunRPC/XDR headers into libtirpc (=/usr/include/tirpc=), so
  on such hosts that =make= fails to find =rpc/types.h= even though
  ChaNGa's *own* =configure= builds fine (its =configure.ac= detects
  =tirpc/netconfig.h= and adds =-I/usr/include/tirpc= + =-ltirpc=
  itself). We can't inject flags through =CFLAGS= — the recipe doesn't
  reference it — so we override =CC=/=CXX= to carry the tirpc paths,
  guarded on the header's presence so it's a no-op on older glibc.
  (One JUBE gotcha, learned the hard way across two failed runs: JUBE
  parses every parameter value as a =separator=-delimited list, and that
  separator defaults to a *comma*. So *any* comma in the preprocess body
  — even inside a shell comment — splits the value, and only one fragment
  survives the =$preprocess= substitution into =submit.job=. The build
  tail vanished and =mpirun= then failed on a never-compiled =./ChaNGa=.
  The whole preprocess block is therefore kept comma-free. This is the
  same mechanism that intentionally turns =nodes: "1,2,4"= into a sweep —
  desirable there, fatal in a script body.)
- *=conv-config.sh= and the =tmp/= symlink.* ChaNGa's =configure=
  derives =CHARM_PATH= from =charmc= and sources
  =$CHARM_PATH/tmp/conv-config.sh=. Charm++'s CMake build keeps
  =conv-config.sh= in =include/= and exposes it via a =tmp -> include=
  symlink, but its =install()= rules copy only =bin/=/=include/=/=lib/=,
  not that symlink — so a CMake-*installed* Charm++ (which is what
  =building-charm.org= produces) is missing =tmp/conv-config.sh=. That
  symlink is recreated in the install prefix by =building-charm.org=, not
  here, so it's shared across workpackages rather than remade per run.

Separately, =testdata='s generator writes =testdata.tbin= inside the
=testdata/= subdirectory, but its =testdata.param= refers to the input by
the bare name =achInFile = testdata.tbin=, which ChaNGa opens relative to
the launch working directory (the workpackage root, where =mpirun= starts
=./ChaNGa=) rather than to the param file's own location. The preprocess
therefore rewrites =achInFile= to =testdata/testdata.tbin=, alongside the
=nSteps= edit, so the run finds its input. Launching from the workpackage
root (rather than =cd='ing into =testdata/=) also keeps the Projections
trace files where the tracing postprocess globs for them.

* Steps

** Running the program

Unlike LeanMD's run step, there's no =fileset= in =use= here — the
source tree is pulled in by =git clone= inside the preprocess step
itself (see the note in the Introduction), not copied in beforehand
by JUBE.

#+name: run_step
#+BEGIN_SRC yaml :eval no
  - name: run-program
    use:
      - globalParameter
      - systemParameter
      - inputset
      - executeset
      - from: platform.xml
        _: jobfiles
      - from: platform.xml
        _: executesub
    do:
      done_file: $done_file
      _: $submit $submit_script
#+END_SRC
