#+title: Building Charm++
#+author: Christian Asch

* Purpose

In this document I will be writing a SLURM script that will build
Charm++ for use in the Kabre cluster of CeNAT. This can then be used
as a guide to building it for other systems.

In the case of Kabre, since the login nodes are different from the
computation nodes it is a good idea to compile the programs that will
run directly on the node as a job.

* Assumptions

You have access to an MPI installation, and you have already
initalized the submodules of the repo.

* Preamble

We only need one node to build the program.

#+BEGIN_SRC bash :tangle build-charm.sh :shebang #!/bin/bash -x
  #SBATCH --job-name=build-charm
  #SBATCH --nodes=1
  #SBATCH --ntasks=20
  #SBATCH --cpus-per-task=1
  #SBATCH --time=10:00:00
  #SBATCH --output=%x-%j.out
  #SBATCH --error=%x-%j.err
  #SBATCH --partition=kura
  #SBATCH --exclusive
#+END_SRC

* Environment

* Building PAPI
I'm following the instructions from their [[https://github.com/icl-utk-edu/papi/wiki/Downloading-and-Installing-PAPI][wiki]].

#+BEGIN_SRC bash :tangle build-charm.sh
  if [ ! -d ${PREFIX} ]; then
      mkdir ${PREFIX}
  fi

  if [ ! -e ${PREFIX}/lib/libpapi.so ]; then
      BUILD_DIR=${DEPS_DIR}/build-papi-${SLURM_JOB_ID}
      echo "Building PAPI"
      cp -r ${DEPS_DIR}/papi/ ${BUILD_DIR}
      pushd ${BUILD_DIR}/src
      ./configure --prefix=${PREFIX}
      make -j
      make install
      popd
      #rm -rf ${BUILD_DIR}
      echo "Built PAPI"
  else
      echo "PAPI already built"
  fi
  export PATH=${PREFIX}/bin:${PATH}
  export LD_LIBRARY_PATH=${PREFIX}/lib:${LD_LIBRARY_PATH}
  export PKG_CONFIG_PATH=${PREFIX}/lib/pkgconfig:${PKG_CONFIG_PATH}
  export CPATH=${PREFIX}/include:${CPATH}
#+END_SRC

* Building Charm++
Now with PAPI built we can build Charm++. We'll do a couple of
versions:

- Base version.
- Base version with Projections.
- Version for changa.
- Version for Changa with Projections.
  
** Base version
#+BEGIN_SRC bash :tangle build-charm.sh
  CHARM_INSTALL_DIR=${PREFIX}/charm-base
  if [ ! -e ${CHARM_INSTALL_DIR}/bin/charmc ]; then
      BUILD_DIR=${DEPS_DIR}/build-base-${SLURM_JOB_ID}
      echo "Building charm++ in $BUILD_DIR, installing in $CHARM_INSTALL_DIR"

      if [ ! -d ${BUILD_DIR} ]; then
  	mkdir ${BUILD_DIR}
      fi

      cmake -S ${CHARM_SRC_DIR} -B ${BUILD_DIR} \
  	  -DCMAKE_BUILD_TYPE=Release \
  	  -DARCH=x86_64 \
  	  -DCMAKE_INSTALL_PREFIX=${CHARM_INSTALL_BASE} \
  	  -DNETWORK=mpi \
  	  -DTARGET=charm++
      cmake --build ${BUILD_DIR} -j
      cmake --install ${BUILD_DIR} --prefix ${CHARM_INSTALL_DIR}

      #rm -rf ${BUILD_DIR}
      echo "Built charm++"
  else
      echo "Charm is already built"
  fi
#+END_SRC

** Projections version

Both Projections-enabled variants (this one and the Changa one below)
pass =-DZLIB=1=. That explicit numeric =1= — rather than relying on the
=ZLIB= option's default — is what actually enables *gzipped* Projections
trace logs (=*.log.gz=), which keep the traces from filling our disk
quota on long runs.

The subtlety is in how Charm++'s CMake build turns options into
=#define=s. =cmake/detect-features.cmake= iterates over every =CMK_*=
CMake variable and writes =#define <name> <value>= into
=include/conv-autoconfig.h= using the value *verbatim* (only ="" /FALSE=
become =0=, =TRUE= becomes =1=). =CMK_USE_ZLIB= is set to the =ZLIB=
option's value, and that option defaults to =ON=. So leaving =ZLIB=
unset emits =#define CMK_USE_ZLIB ON=; because =ON= is not itself a
macro, the C preprocessor evaluates =#if CMK_USE_ZLIB= (in
=src/ck-perf/trace-projections.C=) as =#if 0= and compiles the
compression path *out* — the run-time =+gz-trace= flag is then silently
consumed with a "not supported because Charm++ was built without zlib"
warning. Passing =-DZLIB=1= instead emits =#define CMK_USE_ZLIB 1=, so
=#if CMK_USE_ZLIB= is true.

This is precisely what Charm++'s own =./build= / =buildcmake= wrapper
does (it hardcodes =opt_zlib=1=). We do *not* migrate to that wrapper,
though: it has no way to turn on PAPI (it never passes =-DPAPI=), which
our tracing builds need. Staying on a direct =cmake= call — now with
=-DZLIB=1= alongside =-DPAPI=ON= — is what lets us have both PAPI counters
and compressed traces. (An earlier attempt to force the macro with
=-DEXTRA_OPTS=-DCMK_USE_ZLIB=1= failed because =conv-autoconfig.h='s
=#define CMK_USE_ZLIB ON= is =#include=d into the sources and overrides
the command-line =-D=.) With =-DZLIB=1= the runtime compresses by
default, so no =+gz-trace= run flag is required.

#+BEGIN_SRC bash :tangle build-charm.sh
  CHARM_INSTALL_DIR=${PREFIX}/charm-projections
  if [ ! -e ${CHARM_INSTALL_DIR}/bin/charmc ]; then
      BUILD_DIR=${DEPS_DIR}/build-projections-${SLURM_JOB_ID}
      echo "Building charm++ projections in $BUILD_DIR, installing in $CHARM_INSTALL_DIR"

      if [ ! -d ${BUILD_DIR} ]; then
  	mkdir ${BUILD_DIR}
      fi

      LDFLAGS="$(pkgconf --libs papi)" cmake -S ${CHARM_SRC_DIR} -B ${BUILD_DIR} \
  	  -DCMAKE_BUILD_TYPE=Release \
  	  -DARCH=x86_64 \
  	  -DCMAKE_INSTALL_PREFIX=${CHARM_INSTALL_BASE} \
  	  -DNETWORK=mpi \
  	  -DTRACING=TRUE \
  	  -DPAPI=ON \
  	  -DTRACING_COMMTHREAD=ON \
  	  -DZLIB=1 \
  	  -DTARGET=charm++
      LDFLAGS="-L${PREFIX}/lib" CFLAGS="-I${PREFIX}/include" cmake --build ${BUILD_DIR} -j
      cmake --install ${BUILD_DIR} --prefix ${CHARM_INSTALL_DIR}

      #rm -rf ${BUILD_DIR}
      echo "Built charm++ with projections"
  else
      echo "Charm with projections is already built"
  fi
#+END_SRC

** Changa base version
#+BEGIN_SRC bash :tangle build-charm.sh
  CHARM_INSTALL_DIR=${PREFIX}/charm-changa
  if [ ! -e ${CHARM_INSTALL_DIR}/bin/charmc ]; then
      BUILD_DIR=${DEPS_DIR}/build-changa-${SLURM_JOB_ID}
      echo "Building charm++ changa target in $BUILD_DIR, installing in $CHARM_INSTALL_DIR"

      if [ ! -d ${BUILD_DIR} ]; then
  	mkdir ${BUILD_DIR}
      fi

      cmake -S ${CHARM_SRC_DIR} -B ${BUILD_DIR} \
  	  -DCMAKE_BUILD_TYPE=Release \
  	  -DARCH=x86_64 \
  	  -DCMAKE_INSTALL_PREFIX=${CHARM_INSTALL_BASE} \
  	  -DNETWORK=mpi \
  	  -DTARGET=changa
      cmake --build ${BUILD_DIR} -j
      cmake --install ${BUILD_DIR} --prefix ${CHARM_INSTALL_DIR}

      #rm -rf ${BUILD_DIR}
      echo "Built charm++ with changa target"
  else
      echo "Charm with changa target is already built"
  fi

  # ChaNGa's ./configure sources $CHARM_DIR/tmp/conv-config.sh. Charm's
  # CMake build ships conv-config.sh inside include/ and makes tmp a symlink
  # to it, but the install() rules only copy bin/include/lib — not that
  # symlink — so recreate it in the install prefix. Kept outside the guard
  # above so re-running this script repairs an already-built install without
  # a full rebuild.
  ln -sfn include ${CHARM_INSTALL_DIR}/tmp
#+END_SRC
